# Промпт: продвинутая логика для браузерной "Монополии" (этап 2)

Это продолжение MVP из первого промпта. Скопируй в тот же чат с агентом, где уже есть базовая версия — он должен доработать существующий код, а не переписывать с нуля.

---

Дорабатываю существующую игру. Добавь следующие механики поверх текущего MVP, не ломая то, что уже работает. Двигайся по одному блоку за раз, после каждого — рабочее промежуточное состояние.

## 1. Группы цветов и монополии
- Раздели property на группы (цвета/районы) в конфиге поля — например, 2-3 клетки на группу
- Добавь серверную функцию `hasMonopoly(playerId, groupId)` — проверяет, что игрок владеет всеми property группы
- Пока группа не полностью выкуплена одним игроком — рента базовая. Как только собрана монополия — рента x2 (даже без построек)

## 2. Дома и отели
- Если у игрока монополия на группу — открывается кнопка "Построить дом" на каждой property группы
- Правило равномерной застройки: нельзя построить второй дом на одной клетке группы, пока на остальных клетках группы не построено столько же (упрощённая проверка "разница в этажах ≤ 1")
- Максимум 4 дома на клетку, потом дома меняются на отель (1 отель = "5 домов" по цене/ренте)
- Рента растёт по таблице для каждой property: без построек / 1 дом / 2 дома / 3 дома / 4 дома / отель — задай эти значения в конфиге поля
- Ограниченный банковский фонд домов/отелей не нужен, это упрощение — не делай ограничение по общему количеству домов в игре

## 3. Заклад (мортгейдж)
- Кнопка "Заложить" на property без построек — игрок получает деньги (обычно половина цены), клетка помечается как заложенная, рента с неё не берётся, пока не выкуплена обратно
- Кнопка "Выкупить" — списывает сумму заклада + процент (например 10%) сверху, снимает пометку
- Нельзя заложить клетку, если на ней есть дома — сначала нужно продать дома банку (за половину их стоимости)

## 4. Аукцион
- Если игрок, попавший на свободную property, отказывается её покупать — запускается аукцион среди всех игроков (включая того, кто отказался)
- Простая реализация: по очереди все либо повышают ставку на фиксированный шаг, либо пасуют; когда остался один — он покупает по своей последней ставке
- Стартовая ставка — например 10% от цены клетки
- Таймер на каждую ставку не обязателен, но добавь "пас" для тех, кто явно отказывается участвовать

## 5. Настоящая механика тюрьмы
- Попадание в тюрьму: игрок пропускает броски, пока не выполнит один из вариантов:
  - Выбросит дубль на кубиках (тогда сразу выходит и ходит на выпавшую сумму)
  - Заплатит фиксированный залог (доступно с любого хода в тюрьме)
  - Использует карту "Освобождение из тюрьмы", если она у него есть (добавь такую карту в Шанс/Казну)
- Если провёл в тюрьме 3 хода и не вышел ни одним из способов — обязан заплатить залог на 3-м ходу и выйти

## 6. Торговля между игроками
- Экран/модалка "Предложить сделку": выбрать другого игрока, добавить со своей и с его стороны любую комбинацию — property, деньги, карты "Освобождение из тюрьмы"
- Получатель видит предложение в реальном времени и может: принять / отклонить / отправить встречное предложение (просто новое предложение в ту же сторону)
- При принятии — сервер атомарно обменивает всё указанное между балансами и списками property игроков
- Не давай обменивать property с непогашенным закладом без явного указания в сделке, кто берёт на себя выкуп

## 7. Расширенные карточки Шанс/Казна
- Расширь список карт (10-15 штук на колоду), эффекты сверх простых денежных:
  - Переместиться на конкретную клетку (с/без получения бонуса за проход через Старт)
  - Заплатить/получить от каждого игрока фиксированную сумму
  - Получить карту "Освобождение из тюрьмы" (хранится у игрока до использования)
  - Отправиться в тюрьму немедленно
- Колоды не должны повторять карту, пока не закончится вся колода (тасуй заново, когда все карты вышли)

## 8. Устойчивость к отключениям
- Если игрок отключился во время своего хода — через настраиваемый таймаут (например 60 сек) автоматически пропускай его ход (просто end_turn), чтобы не блокировать остальных
- При переподключении — присылай игроку полный текущий стейт комнаты, чтобы клиент восстановился

## 9. Экран итогов
- При окончании игры (остался один игрок, либо хост завершил) показывай экран с итоговой таблицей: у кого сколько property, домов, финальный баланс, время игры

## Технически
- Вынеси всю новую логику (монополии, застройка, аукцион, тюрьма, торговля) в отдельные модули/функции — не разрастай один файл со всей логикой
- Каждое серверное действие должно возвращать понятную ошибку клиенту, если оно невалидно (например "нельзя строить неравномерно"), а не молча игнорироваться
